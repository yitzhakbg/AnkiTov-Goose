- **Validation script:** `tools/validate_i18n.py` — checks all keys present in all locales, wired in HTML

- **Backend:** `backend/i18n/{code}/main.ftl` (38 Fluent messages per language) + `src/i18n.rs` (compile-time Fluent loader, runtime override, RTL detection)
- **API endpoints:** `GET /api/v1/locale`, `GET /api/v1/locale/info`, `GET /api/v1/locale/list`, `POST /api/v1/locale/set`

## Binding Patterns
- **Static HTML:** `<element data-i18n="key">Fallback</element>` — picked up by I18n.refresh()
- **Dynamic JS:** `el.textContent = t('key')` or `\`${t('key')}\`` — for template-generated content

## Hard Requirement
- Every UI string must have an i18n key (data-i18n or t())
- Every key must exist in ALL locale files
- Field inventory must be updated on every add/change/remove
- Workflow: Add → Translate (all locales) → Wire → Document → Validate → Commit
- Run `python3 tools/validate_i18n.py` before any PR touching i18n

## Adding a New Language
1. Create backend/i18n/{code}/main.ftl (38 messages)
2. Create resources/dashboard/locales/{code}.json (315 keys)
3. Add to SUPPORTED_LOCALES in src/i18n.rs
4. Add handler + route in src/controllers/dashboard.rs
5. Add route in src/app.rs
6. Add <option> in HTML language switcher
7. Add to RTL list in i18n.js if applicable (only ar, he are RTL)
8. Update inventory document
9. Run validator
10. cargo check && cargo test
11. Commit

# AnkiTov i18n System — Complete Reference (2026-07-20)

1. Add key to main.ftl (backend) and JSON files (frontend) for en-US
2. Generate translations for all other locales (via LLM or translator)
3. Wire into imp-console.html (data-i18n for static, t() for dynamic)
4. Update i18n-field-inventory.md
5. Run python3 tools/validate_i18n.py
6. cargo check && restart server
7. Test in all locales, especially RTL (ar, he)
8. Commit with descriptive message

- After dynamic content insertion: call `I18n.refresh()` to apply data-i18n attributes
- For locale switching: reload locale JSON, call I18n.refresh(), toggle .rtl class

# i18n hard-requirement translation-gate non-latin
# Non-Latin Translation Gate (HARD REQUIREMENT — established 2026-07-21)

## The Rule
For every non-Latin-alphabet locale (ar, he, ru, zh, ko, ja), ALL display values in both JSON frontend files and FTL backend files must be translated. NO English words may appear in display values.

## What counts as "English"
Any sequence of 2+ consecutive ASCII letters (a-z, A-Z) that isn't one of the allowed non-translateable tokens.

## Allowed non-translateable tokens (exempt from the check)
- Brand names: AnkiTov, Anki
- File extensions: apkg, xlsx, csv, tsv, CSV, TSV
- Units: MB, min
- Keyboard keys: Shift, Enter, Ctrl, Alt, Tab, Esc, Escape
- Common abbreviations: ID, AI, URL, FAQ
- HTML tag names: h2, h3, p, ol, li, ul, strong, em, div, span, table, tr, th, td, etc.
- HTML entities: amp, nbsp, lt, gt, quot, apos
- HTML attribute values: help, note, help-note, help-table
- Template variable names: count, name, decks, classes, query, created, skipped, enrolled, column, reason, page, days, capsules, entity, detail, etc.

## How to check
Run `python3 tools/validate_i18n.py` — this scans all non-Latin locales for untranslated English and exits with code 2 if any are found.

## When to enforce
This check runs on every translation operation and on demand. It is a HARD GATE — no commit that introduces untranslated English in a non-Latin locale may proceed.

## Current status (as of 2026-07-21)
All 6 non-Latin locales have ~61-72 untranslated keys each (frontend JSON) plus 15 untranslated keys each (backend FTL). These need to be translated before the gate can pass.
