# AnkiTov i18n system — distilled 2026-11-16 (full history: AnkiTov-goose/memory/archive/2026-11-16-pre-prune/i18n-system.txt)

## ARCHITECTURE
- Frontend: backend/resources/dashboard/locales/{code}.json (315 keys/locale) + i18n.js runtime (t(), data-i18n binding, RTL toggle) + rtl.css.
- Backend: backend/i18n/{code}/main.ftl (38 Fluent messages) + src/i18n.rs (compile-time Fluent loader, runtime override, RTL detection).
- API: GET /api/v1/locale, /locale/info, /locale/list; POST /locale/set.

## LOCALES (11)
en-US (LTR), ar (RTL), he (RTL), fr, es, it, ru, zh, ko, ja (LTR).

## BINDING PATTERNS
- Static HTML: <element data-i18n="key">Fallback</element> → I18n.refresh().
- Dynamic JS: el.textContent = t('key').

## HARD REQUIREMENT (Non-Latin Translation Gate, 2026-07-21)
- Every UI string must have an i18n key; every key must exist in ALL locale files.
- For ar/he/ru/zh/ko/ja: NO English words in display values (2+ consecutive ASCII letters = violation, except allowed tokens: apkg, xlsx, csv, tsv, MB, KB, etc.).
- Run python3 tools/validate_i18n.py before any PR touching i18n (exits non-zero on violations).
- Field inventory: workspace/i18n-field-inventory.md must be updated on every add/change/remove.

## ADDING A LANGUAGE (checklist)
1. backend/i18n/{code}/main.ftl (38 msgs) → 2. locales/{code}.json (315 keys) → 3. SUPPORTED_LOCALES in src/i18n.rs → 4. handler + route in controllers/dashboard.rs → 5. route in app.rs → 6. <option> in HTML switcher → 7. RTL list in i18n.js if RTL → 8. update inventory → 9. run validator → 10. cargo check && cargo test → 11. commit.
